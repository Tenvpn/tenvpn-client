# TENVPN на Windows

Сессия 5 (17.10.2026). Как устроены права, трей, автозапуск, установщик и обновления на Windows.

## Права на TUN

TUN (весь трафик компьютера) требует прав администратора. Их держит служба `TENVPNHelperService` (Rust, `services/helper`): она запускается от SYSTEM и стартует ядро `TENVPNCore.exe`, только если его SHA-256 совпадает с вшитым при сборке (`libclash/windows/manifest.json`).

- **Установщик** регистрирует службу сам (`TENVPNHelperService.exe install` в `[Run]` скрипта Inno Setup) — установщик уже работает с правами администратора, поэтому приложение потом включает TUN без запроса UAC.
- **Портативная сборка** (zip) регистрирует службу при первом включении TUN: один запрос UAC (`System.authorizeCore` → `runas`).
- **Отказ в UAC или служба недоступна** — приложение не ломается: TUN не включается, работает системный прокси (`NetworkProps.systemProxy`, по умолчанию включён). Когда TUN разрешён, системный прокси не ставится (`proxyStateProvider`): весь трафик и так идёт через TUN, а прокси поверх оставил бы браузеры без сети при падении ядра.
- **Настройка «Весь трафик через VPN»** (Настройки → Подключение, только Windows) — выключить TUN вручную, если мешает другой VPN; тогда работает системный прокси.

Удаление программы останавливает и удаляет службу (`InitializeUninstall`).

## Настройки по умолчанию на Windows

Свежая установка (`Config.fresh(isWindows: true)`): TUN включён, протокол «Сначала AmneziaWG» (`awgPriority`). Выбор пользователя сохраняется и дальше не перетирается. Сборщик конфигурации (`lib/tenvpn/configgen`) не менялся — приоритет AWG задаётся опцией `ConfigGenOptions.autoStrategy`.

## Трей

Короткое меню TENVPN (`AppTray._buildTenvpnMenu`): «Открыть TENVPN», «Подключить/Отключить», «Переподключиться» (выключить и включить: рвёт зависшие соединения, «Авто» выбирает заново), «Сервер» (Авто + все серверы, как на главном экране), «Запускать вместе с Windows», «Выход». Подсказка иконки — «TENVPN · Включено». Полное меню апстрима (режимы, группы, TUN/прокси) — в режиме разработчика.

Закрытие окна крестиком прячет его в трей (`minimizeOnExit`, по умолчанию включено); выход — только из меню трея.

## Автозапуск

`HKCU\…\Run\TENVPN = "C:\…\TENVPN.exe" --autostart` (путь в кавычках). С `--autostart` окно не показывается — приложение стартует в трее; подключение — по настройке «Подключаться при запуске». Удаление программы чистит запись в `Run` и задачу планировщика `TENVPN`.

## Установщик

`windows/packaging/exe/inno_setup.iss` (шаблон `flutter_distributor`), сборка: `dart setup.dart windows --arch amd64` (нужен Inno Setup 6 в `PATH` или в стандартном месте; в CI он есть на раннере `windows-2022`).

Параметры командной строки установщика: стандартные Inno (`/SILENT`, `/VERYSILENT`, `/SUPPRESSMSGBOXES`, `/DIR=`) и `/relaunch=<аргументы>` — с чем запустить приложение после тихой установки (обновление передаёт `--connect`).

## Обновления

При запуске (и кнопкой «Проверить обновления» в настройках) приложение читает `releases/latest` репозитория `repository` (`lib/common/constant.dart`) или адрес из `TENVPN_RELEASES_URL` (переменная окружения сборки → `env.json`; тот же JSON, что у GitHub — для зеркала). Если версия новее:

1. диалог «Новая версия …» с заметками выпуска — «Обновить» / «Позже»;
2. скачивается `TENVPN-<версия>-windows-amd64-setup.exe` из выпуска и `SHA256SUMS.txt`; хеш сверяется, битый файл удаляется;
3. установщик запускается с `runas` (UAC) и `/SILENT /SUPPRESSMSGBOXES /NORESTART /SP- [/relaunch=--connect]`, приложение выходит;
4. установщик переустанавливает службу и запускает новую версию; если VPN был включён — она подключается сама (`--connect`).

Портативная сборка обновлений сама не ставит — открывает страницу выпуска.

**Подлинность.** Сейчас защищает только HTTPS до GitHub и сверка хеша из того же выпуска (от битых загрузок). После покупки подписи кода — проверять Authenticode установщика перед запуском (`WinVerifyTrust`, издатель TENVPN).

**Требование к выпуску:** в релизе должны лежать `…-windows-amd64-setup.exe` и `SHA256SUMS.txt` (их кладёт `.github/workflows/build.yaml`), а репозиторий `repository` — быть публичным, иначе GitHub API отвечает 404 и обновления молчат.
