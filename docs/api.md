# API, с которым работает клиент TENVPN

**Версия 1 · 17.10.2026 · сессия 2.** Здесь — контракт между приложением и серверной частью TENVPN. Домены, токены и UUID в примерах выдуманы (`example.com`, `sub.example.com`, `api.example.com`).

Приложение ходит в два места:

| Источник | Кто отдаёт | Что берём | Обязателен |
|---|---|---|---|
| Подписка | панель Remnawave | серверы VLESS (Reality, gRPC, WS, xhttp) и Hysteria2 | да |
| AWG-конфиг | бэкенд TENVPN (репо vpnbot) | один wireguard-сервер с опциями AmneziaWG | нет |

Из двух источников модуль `lib/tenvpn/configgen/` собирает итоговый mihomo-конфиг (§3). Без AWG приложение работает как раньше; падение AWG-источника никогда не ломает подписку.

---

## 1. Подписка Remnawave

```
GET https://sub.example.com/<shortUuid>
User-Agent: mihomo TENVPN/v0.1.0 Platform/android
```

**User-Agent обязан начинаться с `mihomo`.** Панель выбирает формат по первому слову: на `mihomo …` отдаёт YAML, на всё остальное (в том числе `TENVPN/…`) — base64 со ссылками `vless://`. Строка собирается в `lib/common/package.dart`. Если всё же пришли ссылки, configgen бросает `ConfigGenException(shareLinks)` с понятным текстом — пустой профиль больше не создаётся.

### Заголовки ответа, которые читает приложение

| Заголовок | Пример | Что делаем |
|---|---|---|
| `subscription-userinfo` | `upload=0; download=0; total=0; expire=1792477391` | трафик и дата окончания (`expire` — unix-время), показывается в профиле |
| `profile-title` | `base64:VEVOIFZQTg==` | имя профиля («TEN VPN»); приоритетнее `content-disposition` |
| `content-disposition` | `attachment; filename=user_123` | запасное имя профиля |
| `profile-update-interval` | `1` | часы; задаёт интервал автообновления **нового** профиля, зажимается в 1–24 ч |

Остальные (`announce`, `support-url`, `profile-web-page-url`, `routing`) пока не используются — кандидаты для сессии 4.

### Тело

mihomo-YAML. Из него configgen берёт **только `proxies`**, всё остальное (порты, `mode: global`, DNS, группа `→ Remnawave`, `rules`) заменяется своим (§3). Каждая запись `proxies` переносится поле в поле, без нормализации: проверено на живой подписке — 12 серверов, 250 полей, 0 расхождений, включая все ключи xhttp (`x-padding-*`, `session-*`, `seq-*`, `uplink-*`, `sc-*`, `reuse-settings` = xmux).

**Разделители.** Панель кладёт в список «заголовки» вида `👇 Серверы для обхода белых списков 👇` — это прокси с заведомо нерабочим адресом (`server: '127'`). Признак разделителя — `server` не IP и не доменное имя (`isRoutableHost`). Разделитель в конфиг не попадает, а все серверы после него получают метку раздела («Серверы для обхода белых списков») — её берёт интерфейс сессии 3.

**Конфликты имён.** Повтор имени или имя, совпадающее с группами приложения (`TENVPN`, `Авто`, `Вручную`) или встроенными (`DIRECT`, `REJECT`, …), получает суффикс ` (2)`: иначе ядро падает на «loop is detected» / «duplicate name».

## 2. AWG-конфиг из личной админки

**Статус на 17.10.2026: эндпоинта на сервере нет.** Клиент готов и работает на моке; серверная задача описана в отчёте сессии 2 (`tenvpn-infra/docs/client-app/reports/session-2-report.md`).

### Запрос

```
GET https://api.example.com/api/app/v1/awg
Authorization: Bearer <app_token>
Accept: application/json
User-Agent: mihomo TENVPN/v0.1.0 Platform/android
```

- `app_token` — токен **устройства** приложения. Его выдаёт бот вместе с deep link (сессия 4), по нему бэкенд находит пользователя и устройство (`devices.id`), а значит, и AWG-пира этого устройства (`awg_peers`). Токен не равен `shortUuid` подписки: подписка — на пользователя, AWG-пир — на устройство.
- Полный URL эндпоинта приложение хранит вместе с токеном (§4), путь не зашит в код.
- Запрос идёт вместе с обновлением подписки: при добавлении профиля, при старте приложения (если профиль старше 15 минут) и по расписанию автообновления.

### Ответ 200

```json
{
  "version": 1,
  "name": "🛡 Запасное подключение",
  "protocol": "2.0",
  "conf": "[Interface]\nPrivateKey = …\nAddress = 10.66.0.42/32\n…",
  "updated_at": "2026-10-17T07:00:00Z"
}
```

| Поле | Тип | Обязательно | Смысл |
|---|---|---|---|
| `version` | int | да | версия формата ответа; клиент понимает только `1`, на другую реагирует как на «недоступно» |
| `conf` | string | да | `.conf` в формате wg-quick — **тот же текст, что бот отдаёт файлом для AmneziaVPN** (`awg/provider.py → render_awg_config`) |
| `name` | string | нет | имя сервера в списке; по умолчанию «🛡 Запасное подключение» |
| `protocol` | string | нет | версия профиля AWG (`"2.0"`, `"1.x"`), справочно |
| `updated_at` | string | нет | ISO-8601, справочно |

Заголовок `Cache-Control: no-store` обязателен: в `conf` приватный ключ пира.

**Почему `.conf` текстом, а не разобранными полями.** Рендер `.conf` в боте уже один и проверен на AmneziaVPN; второй формат означал бы второй рендер и рассинхрон. Разбор живёт в клиенте (`parseAwgConf`) и покрыт тестами на профилях 1.x и 2.0.

### Что клиент понимает в `conf`

`[Interface]`: `PrivateKey`, `Address` (IPv4 и/или IPv6, через запятую), `DNS`, `MTU`, `Jc`, `Jmin`, `Jmax`, `S1`–`S4`, `H1`–`H4` (число или диапазон `a-b`), `I1`–`I5`, `J1`–`J3`, `Itime`.
`[Peer]`: `PublicKey`, `PresharedKey`, `Endpoint` (`host:port` или `[v6]:port`), `AllowedIPs`, `PersistentKeepalive`.

Ключи — стандартный base64 с `=` на конце (44 символа), не urlsafe. Если в `[Interface]` нет ни одной ненулевой опции обфускации, сервер считается обычным WireGuard (без `amnezia-wg-option`).

В mihomo это превращается в:

```yaml
- name: 🛡 Запасное подключение
  type: wireguard
  server: 192.0.2.50
  port: 47213
  ip: 10.66.0.42
  private-key: …
  public-key: …
  pre-shared-key: …
  allowed-ips: ['0.0.0.0/0']
  udp: true
  mtu: 1280
  persistent-keepalive: 25
  remote-dns-resolve: true
  dns: [1.1.1.1, 1.0.0.1]
  amnezia-wg-option: {jc: 4, jmin: 40, jmax: 70, s1: 15, s2: 23, s3: 18, s4: 9,
                      h1: '172006388-202361271', h2: …, h3: …, h4: …}
```

### Коды ответа и поведение клиента

| Ответ | Смысл для бэкенда | Что делает клиент |
|---|---|---|
| `200` + валидное тело | AWG есть | кладёт `conf` в кэш, добавляет сервер в «Авто» и «Вручную» |
| `200`, но `conf` не разбирается | ошибка рендера | пишет в лог, **оставляет прежний кэш** |
| `401`, `403` | токен недействителен / отозван | удаляет AWG и кэш |
| `404` | у пользователя нет AWG (флаг выключен, не в пилоте) | удаляет AWG и кэш |
| `410` | устройство удалено | удаляет AWG и кэш |
| `402`, `429`, `5xx`, таймаут 10 с, не JSON, `version ≠ 1` | временная проблема | оставляет кэш, пробует при следующем обновлении |

Тело ошибок — `{"error": "<код>"}` в духе существующих `/api/awg/*` (`awg_unavailable`, `device_removed`, `not_found`); клиент смотрит только на статус.

Выключение пира при нулевом балансе бэкенд делает на AWG-сервере (как сейчас). Клиенту отдельный код для этого не нужен: сервер просто перестанет проходить проверку задержки, и «Авто» уйдёт на другие.

## 3. Что собирает configgen

Вход: тело подписки (§1) и, если есть, AWG-конфиг (§2). Выход: YAML, который сохраняется файлом профиля и проверяется ядром до записи.

| Ключ | Значение |
|---|---|
| `proxies` | серверы подписки без разделителей + AWG последним |
| `proxy-groups` | `TENVPN` (select: `Авто`, `Вручную`) → `Авто` (url-test по всем серверам, `generate_204`, 300 с, допуск 50 мс) и `Вручную` (select по всем) |
| `rules` | частные сети (`10/8`, `172.16/12`, `192.168/16`, `127/8`, `169.254/16`, `100.64/10`, `fc00::/7`, `fe80::/10`) — `DIRECT`, остальное — `MATCH,TENVPN` |
| `dns` | `fake-ip`; `default-nameserver` 77.88.8.8, 1.1.1.1; `nameserver` DoH 1.1.1.1 + 77.88.8.8; `proxy-server-nameserver` 77.88.8.8, 77.88.8.1, 1.1.1.1. Яндекс первым, чтобы адреса серверов находились и в сетях с белыми списками; китайских резолверов апстрима нет |
| `tun` | `enable`, `stack: mixed`, `auto-route`, `auto-detect-interface`, `dns-hijack: any:53` |
| `external-controller` | `127.0.0.1:9090` и случайный 128-битный `secret` при каждой сборке |

Режим «AWG приоритет» (`AutoStrategy.awgFirst`, для Windows в сессии 3): `Авто` становится `fallback` [AWG, скрытая url-test группа `Авто · пул`].

**Внутри приложения часть ключей перекрывает слой настроек** (`_makeRealProfileTask`, `lib/common/task.dart`): порты, `mode`, `tun` (из настроек VPN), `external-controller` и `secret` (по умолчанию контроллер выключен — приложение говорит с ядром через JNI/IPC, а не REST). DNS из профиля остаётся, пока в настройках не включено «Переопределить DNS»; дефолты этой настройки теперь те же, что в таблице выше. Секрет и контроллер из configgen работают, когда конфиг запускается ядром напрямую (`tool/configgen.dart` + `mihomo -f`).

## 4. Откуда приложение берёт адрес и токен AWG

Временно, до сессии 4 — параметрами существующей ссылки импорта (значения URL-кодируются):

```
tenvpn://install-config?url=<подписка>&awg=<полный URL §2>&awg_token=<app_token>
```

Без `awg`/`awg_token` ссылка работает как раньше — только подписка. Хранится пара в `<каталог данных>/tenvpn/<id профиля>.json` вместе с кэшем `conf` и списком серверов с разделами; файл удаляется вместе с профилем. Сессия 4 вводит `tenvpn://import?sub=<url>&token=<…>` и базовый адрес бэкенда в настройках сборки — тогда `awg` из ссылки уйдёт, а `token` станет общим для AWG и эндпоинта «баланс / истекает / устройства».

## 5. Мок

`tool/awg_mock.py` — HTTP-заглушка: отдаёт ответ §2 по `GET /api/app/v1/awg` с проверкой `Bearer`, а `GET /mode/<статус>` переключает её на ответ с нужным кодом.

```bash
python tool/awg_mock.py awg.conf <token> 18787
adb reverse tcp:18787 tcp:18787
```

В ссылке импорта — `awg=http://127.0.0.1:18787/api/app/v1/awg&awg_token=<token>`. Порт 8787 на машине разработки занят системным исключением Windows, поэтому 18787. В тестах ту же роль играет подменный транспорт (`test/tenvpn/tenvpn_config_test.dart`).
